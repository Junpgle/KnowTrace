# KnowTrace v1.2.0 — AI 知识点审核

## 界面入口

1. 在「资料导入与管理」上传并批量提取 PDF/PPTX 知识点。
2. 在「题库管理 → 1. 知识点审核」打开新增的 **AI 知识点预审** 面板。
3. 选择默认模型、MiMo 或本地 Ollama；云端调用必须先确认课件片段会发给第三方且可能收费。
4. 点击「审核当前知识点」，或「批量 AI 预审」。批量任务每个知识点单独分析并持久化检查点，支持「完成本项后停止」与中断后继续。
5. 查看 AI 建议（通过/复核修改/驳回）、具体理由、逐字引用和是否经过程序核验。
6. 仅当同时满足「模型建议通过、信心高、原文文字片段逐字证据匹配、无问题提示、知识点仍是待审核且未被修改」时，才进入「可批量采纳建议」列表。用户必须勾选并明确确认才能让知识点的正式状态变成 approved。原有人工审核按钮仍可使用。

## 审核链路

- **证据核对**：只读取知识点关联的本课程课件，模型输入最多两个片段、各1800字符。程序核对引用的 source_chunk_id 真实存在、引文是该片段连续十字以上的原文、片段类型为 text。AI 的自评信心是参考信息，不是统计校准的准确度。
- **语义检查**：MiMo / Ollama 对照来源审查名称、摘要、过度推论、概念错误、难度异常、同名重复。模型不能凭空补充课外知识，也不能把课件中的指令当作新的操作指令。
- **视觉安全**：figure_description 来自 AI 图片阅读、并未经过人工对照 PDF 原图，即使识别出的片段文字与描述相符，也不会进入自动采纳列表。应打开原始 PDF 查看。
- **防止过期**：AI 结果保存知识点内容及来源文本的 SHA-256 快照指纹。任何实质修改、原文变更或人工决议后，旧结果会被标记为 stale，无法采纳。修改后可重新执行单点或批量预审。
- **重复识别**：同名知识点（忽略空白及大小写）被硬性标记为需人工检查；近义重复检测依赖模型，不会自动删除或合并已有知识点。
- **正式记录**：批量采纳通过单独的确认 API 写入知识点 review_status 和已有 knowledge_point_events 审核事件，其中明确标注关联的 ai_review_id。模型调用本身永远不自动批准。
- **失败恢复**：批量任务状态记录在 ai_knowledge_review_batches，完成一个知识点后写入检查点。停止仅在单个模型请求结束时生效；模型错误暂停，修复配置后可继续。后端重启后原有运行任务会标记为 interrupted，可手动恢复。当前是本地单 worker 的 MVP，不支持多进程并发队列。

## API

- POST /api/knowledge-points/{kp_id}/ai-review ：单个预审
- GET /api/courses/{course_id}/ai-knowledge-reviews ：最近一次建议
- POST /api/courses/{course_id}/ai-knowledge-reviews/apply ：显式 confirmed=true，审核采纳
- POST /api/courses/{course_id}/ai-review-batches ：启动批量预审，支持 provider 及 limit（最多1000，默认200）
- GET /api/courses/{course_id}/ai-review-batches ：任务历史、进度与错误
- POST /api/ai-review-batches/{batch_id}/stop ：协作停止
- POST /api/ai-review-batches/{batch_id}/resume ：继续任务

## 费用及隐私

默认 provider 可能配置为 MiMo。只有用户勾选云端费用/共享确认后，前端才允许发起相应预审。若要完全本地运行请明确选择 Ollama。MiMo 调用按知识点计费；建议先对一个知识点测试，再批量运行。

本地 KnowTrace 目前没有完整多用户鉴权，请勿将后端端口暴露到公网。

## 尚未支持

- 不能把高信心等同于真实正确率；即使使用了逐字引用，学术概念的完整性和因果解释也可能需要人类判断。
- 图片原始内容的 AI 二次交叉审核尚未集成：视觉生成的知识点需逐条人工核对原图。
- 尚未提供正式的 AI 自动改写、合并重复知识点或无人值守自动通过模式，以免错误进入正式题库和 BKT。
- 本功能只审核知识点，题目审核仍使用原题库内独立人工审核功能。
