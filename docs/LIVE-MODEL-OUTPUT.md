# KnowTrace — 关系构图 AI 的实时可见回复

## 使用入口

打开「知识星系 · 3D → 提取 / 审核关系」，选择「章节内相似分组」或「跨章节桥接」，开始分析。当前组的进度卡片新增 **「模型实时回复」**，默认展开：

- 模型请求已送达、等待首个输出时，显示「等待首个字」。
- 模型返回可见文本时，约每 650 毫秒更新页面（不需要等完整一组分析完毕）；显示当前组序号、已接收字符数和实时生成的 JSON 答案。
- 可以收起面板、关闭自动滚动；关闭面板不影响后端模型运行。
- 原始显示最多保留最近 16,000 字符，避免 1300+ 知识点的长期任务占满内存；后端仍使用完整回答进行验证。
- 已完成本组模型输出后，后端必须对知识点 ID、原文引用、来源片段 ID、关系方向等进行完整校验。仅合法关系会保存为待审核候选。展示中的部分 JSON 不会保存为知识边。
- 旧版逐点关系模式尚未接入增量回复，推荐使用分组和跨章节桥接模式。

## 传输方式

模型到后端是真正的流式响应：

- **MiMo**：通过 OpenAI-compatible Chat Completions 的 `stream: true`，解析 SSE `data: ...` 的 `choices[].delta.content`。
- **Ollama**：通过本机 `/api/generate` 的 `stream: true`，解析 NDJSON 的 `response` 字段。
- 前端：调用 `GET /api/relation-batches/{job_id}/live`，每约650毫秒读取正在生成的快照，延迟由网络、浏览器调度与模型分块速度决定，并非精确的 Token 级实时推送。
- 不显示也不缓存模型 `reasoning_content` 或 `thinking` 内部推理字段；这是一份 **模型对用户可见的生成结果**，不是其内部思维链。
- 单次流式请求断开/被截断不会被视作成功，不会将不完整的 JSON 当作合法关系保存；任务暂停后可重试当前组（模型供应商可能对已发送请求计费）。
- 分组任务进度、检查点、结果保存在原有 SQLite；正在生成的可见文本仅在当前后端进程的有界内存缓存中，不写入数据库。后端重启后这份临时显示会消失，但已完成分组和候选关系不会丢失。

## 局限与安全

- 输出文本可能包含模型逐字引用的课件片段，所以仅应在本地单用户环境查看，切勿对公网开放 FastAPI。
- 网络或模型在首个分块前迟迟无响应时，界面只能提示等待，无法展示不存在的可见内容。
- 不保证所有模型都提供连续均匀的分块；不同版本可能一次发出长文本。
- 当前增量原文预览针对「章节内 / 跨章节」关系构图任务；整份资料知识点提取、题目生成、AI 预审的实时生成文本暂未接入这一面板，它们仍由已有任务中心显示页码、任务状态与完成通知。

## 验证

后端测试 `backend/tests/test_relation_streaming.py` 校验 MiMo SSE、Ollama NDJSON、隐藏推理过滤与中断安全；
`backend/tests/test_grouped_relations.py` 校验在模型尚未完成时能够查询当前 JSON 片段，且不会提前生成知识关系。
前端 CI 运行 Vue TypeScript 校验和 Vite 打包。
