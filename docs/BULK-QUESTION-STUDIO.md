# KnowTrace 智能批量题库（第一阶段）

## 使用方法

打开「题库管理 → 3. 智能批量题库」，选择章节、AI 服务、知识簇大小（首次建议 4）、分组数量（首次建议 1）和每组题量，确认可能产生的模型费用后开始。生成题目统一进入「2. AI 题目审核」。更新仓库后继续使用原启动脚本，**无需删除数据库或重新导入 PDF**。

## 分组与覆盖

- 仅使用已审核、未归档、具备已就绪课件来源的知识点。
- 有章节 ID 的按真实章节分桶；无章节的按原始 PDF 文档分桶。
- 使用已审核知识关系与相同来源文档辅助组内排序，不把图谱视觉距离当作真实先修关系。每组 2–12 个知识点，前端首次试运行默认 4 个。
- 最新题目版本为待审核或已审核的已关联知识点不再参与当前补题；已驳回、草稿及旧版本不算覆盖。一个知识簇不保证组内每个点都被新题覆盖。
- 页面分开展示「已审核题目覆盖」和「待审核题目涉及」，两者可能重叠，不可直接相加。
- 最多每次 50 个分组，每组最多 4 道候选题；首次试运行默认 1 组 × 1 道。MiMo 可能按 Token 收费，需要用户明确勾选确认。

## 一题多知识点

每道题输出主考查知识点 ID、1–4 个实际考查知识点 ID、每个关联点的证据（精确来源 chunk_id 和逐字引文）。后端拒绝不合法 ID、缺乏来源的关联、引文不匹配、重复题干和无效题型；合格候选题的多点映射写入原有 question_knowledge_points 表。

**引用存在不代表答案正确。** 综合题是否真正考查对应知识点、单选是否唯一正确、干扰选项与解析是否合理，都必须人工审核。AI 图像描述作为资料时尤其需要回看 PDF。所有生成题目均为 pending，不能自动批准。

**掌握度限制**：BKT 仍是单知识点诊断模型，综合题只保存练习结果，不更新任一关联知识点的 BKT。最新已审核题目的 Q 矩阵可通过 /api/courses/{course_id}/q-matrix 检索；它是题目—知识点映射，不等同于已经校准的诊断模型。

## 断点续跑

SQLite 增量新增 question_generation_batches、question_generation_units 两张表，原有历史题库不清空、不覆盖。每个知识簇为独立检查点；成功后不自动重新运行。刷新网页无影响；关闭后端会把运行中的批次标为 interrupted，需重启后**手动**恢复，以降低重复付费风险。停止命令会等待当前 AI 请求结束才生效；已经发送的请求仍可能被供应商计费。

## API

- GET /api/courses/{course_id}/question-batches/preview?group_size=8 — 课程覆盖与候选计划（可选 chapter_id）。
- POST /api/courses/{course_id}/question-batches — 创建，需要 confirmed=true。
- GET /api/courses/{course_id}/question-batches — 历史批次与检查点。
- GET /api/question-batches/{batch_id} — 任务详情。
- POST /api/question-batches/{batch_id}/stop、/resume — 停止与恢复。

示例请求：

~~~json
{
  "provider": "default",
  "chapter_id": null,
  "group_size": 4,
  "max_groups": 1,
  "questions_per_group": 1,
  "question_types": ["single_choice", "true_false"],
  "confirmed": true
}
~~~

## 阶段性限制

当前只支持单选题和判断题。模型上下文只传送与当前知识簇有关的限量片段，不会整本上传 PDF。此阶段尚未开发多选、简答、填空、正式自动组卷。现已支持简单的「薄弱点优先」单知识点选题，但不是经校准的多知识点认知诊断模型。生成状态采用单机进程内后台线程，适用于可信的本地单用户场景，不适合多实例或公网直接部署。

已增补测试，覆盖来源校验、一题多点存储、状态持久化以及重启后的自动跳过。

## 生成失败时的处理

1. 首先展开失败任务的「检查点明细」，阅读具体失败原因。返回的 last_error 来源于后台保存的任务状态。
2. 如果提示 JSON 格式不完整，先从「4 个知识点 / 1 组 / 每组 1 道题」开始，使用稳定支持 JSON 的模型。后端可容忍 Markdown JSON 代码块，但不会默默补全截断的题目。
3. 如果提示 source quotation not found 或缺乏来源证据，说明候选未能找到对应课件原文，会被拒绝，不会入库。可检查 PDF 提取质量与审核状态。
4. 如果出现 MiMo Key、网络连接或 Ollama 模型配置错误，先检查「AI 模型设置」，不要盲目连续重试可能已计费的请求。
5. 刷新页面不会清除已成功分组。服务重启或明确失败不会自动重复调用 AI；只有用户点击「继续」才会重试失败组，成功组仍跳过。

GitHub 连接器不能访问本机数据库或运行日志。升级后仍失败请提供任务卡中的具体错误文字。
