# KnowTrace v1.3.0 — AI 任务中心与知识点直接批量通过

## 为什么要做任务中心

过去的资料库只在当前文档组件里监测批处理。用户同时对多份 PDF/PPTX 发起提取、切换课程或页面后，很难知道是哪份资料完成、失败，以及失败发生在第几页。

现在顶部导航栏有铃铛 **「AI 任务与通知」**。默认每约 1.8 秒轮询后台：正在运行 / 排队 / 等待停止的任务各自显示资料名、课程、页数、已成功处理的批次和模型调用中的页码。进度是已经提交成功的页面数，不伪装显示模型请求内部的 Token 进度。

## 并发与通知

- 单页选择和整份资料均使用统一的 `batch_extractions` 表。选定页面任务最多4页；整份文档按1–4页分批运行。
- 本地单进程 FastAPI 运行模式下同时最多执行2个AI提取请求，其余等待；避免无限并发导致 MiMo API 限流。多 worker / 多实例部署不在本版本支持范围。
- 每个任务都有自己的文档 ID、任务 ID 和来源，失败不会覆盖其他任务的状态。处理成功（产生知识点）、处理完但没有生成知识点、失败、人工停止和服务重启中断都分别写入 `task_notifications`。
- **顶部通知弹窗**：页面打开期间收到新事件时显示 8.5 秒；历史通知、未读计数和失败信息保留在本机数据库，即使刷新或切换资料也能在铃铛中查看。
- 失败状态可在任务中心点击继续 / 重试，从上次提交成功的批次继续，不重跑已保存的页面。超时前已被云端计费的请求可能在重试时再次收费。
- 当前单次模型调用尚不能精确展示百分比；任务中心显示“正在分析第 X–Y 页”，这段时间完成比例不会跳动。

## API

- `POST /api/documents/{id}/batch-extractions`：现在还接受可选 `page_start` / `page_end`，可建立选定页面异步任务。
- `GET /api/task-center`：所有课程最近的任务、持久化通知、未读数、并发上限。
- `POST /api/task-center/notifications/read`：标记通知已读。
- `GET /api/batch-extractions/{id}`：单任务快照，包括 `range_start`、`range_end`、`work_stage`、`in_flight_start/end`。
- `POST /api/batch-extractions/{id}/stop` 和 `/resume`：批次边界停止、失败续跑。

现有数据会在启动时通过加列迁移扩展，不清空已有资料或知识点。原有记录在创建任务时没有新的区间字段，则按整份文档解释。

## AI 知识点直接批量通过（不必二次 AI）

进入 **题库管理 → 知识点审核 → 信任模型结果 · 直接批量通过**：

1. 默认展示 AI 生成的待审核知识点（可切换显示全部待审核）。
2. 勾选单个、多个，或全选有课件来源的项。
3. 标记纯图片 AI 来源和同名重复风险；无课程证据的项不可选择。
4. 勾选明确确认后直接批准，不会调用任何第二次模型审核，也不消耗 AI Token。
5. 已批准、已归档、跨课程、无关联课件证据或审核状态已变化的项，服务端会跳过。
6. 结果会写入正常的 `knowledge_point_events`，明确标注为用户主动跳过 AI 复审的批量批准。

**请注意**：程序核对有课件来源，不等于学术内容已经准确。图片识别幻觉、概念错误和近义重复仍可能存在。可先少量通过测试学习/出题效果；如果想更严格，可继续使用上一版的 AI 预审或手动逐条核对。

### API

- `GET /api/courses/{course_id}/knowledge-points/bulk-approval-preview`
- `POST /api/courses/{course_id}/knowledge-points/bulk-approve`
  - JSON: `{"confirmed":true,"bypass_ai_review":true,"point_ids":["..."]}`
  - 最大2000个 ID；服务端在一个数据库事务里逐项重新校验资格、写入审批历史。

## 验证

- 后端回归测试：三份文档并行、两个实际模型请求并发、一份成功另一份失败后的独立通知、选页任务、失败续跑、旧库迁移、直接批量通过的权限和证据保护。
- 前端 CI：Vue TypeScript 检查、Vite 生产构建。

更新：`git pull origin main`，重启 FastAPI 后端并刷新浏览器。建议单进程方式运行；使用 `uvicorn ... --workers N` 时，进程内并发限额无法在 worker 之间共享。
